Cadences — nobody falls through the cracks
A playbook of follow-ups, running in the background
A cadence is your team's follow-up playbook — "after a demo, send this email, wait two days, call, then follow up with a LinkedIn note". Build it once, and Horilla runs it for every new lead, contact, account, campaign or deal. A rep can also enroll or un-enroll a record by hand; each run keeps its own activities, and earlier runs stay on the Cadence tab. No more forgotten follow-ups, no more cold leads going silent.
Three step types that cover everything
Send an email — from a reusable, rich-text template
Make a call — a task lands in the rep's queue
Do something — a custom task (send sample, post proposal, etc.)
Precise timing between steps
Immediately — fire the next step the instant the previous finishes
Minutes, hours, days or months later
Only if the previous step was completed, skipped, or went overdue
Smart branching — not a rigid script
Yes/No paths — different follow-up if they reply vs. go silent
Conditional steps — only run if score > 50, or if deal size > $10k
Shared email templates — update the template, every cadence updates
See progress per contact — what's done, pending, overdue
Enroll by hand — start or stop a cadence on the record
Completion reports — which cadences work, which don't
Example: "Two days after the discovery call, if they opened the follow-up email, send a case study. If they didn't, book a call with the champion."

Workflow automation — your team's robot assistant
WorkflowRule engine · Scheduler · Execution history
Fire workflows on the moment that matters
When a record is created — e.g. new big deal created → alert the VP
When it's updated — e.g. stage moves to Negotiation → notify legal
When it's deleted — e.g. account closed → archive with history
On a schedule, relative to a date — "3 days before close date"
WorkflowRule / WorkflowCondition / WorkflowAction models for modular rule design
Pick what happens when it fires
Send a polished email (using a template)
Pop an in-app notification
Or both — for things nobody should miss
Only fire when the conditions are right

Combine "equals", "not equals", "greater/less than", "contains" and more with AND/OR — so alerts only reach the right people in the right situation, not on every change.

Real examples that save hours per week

1 day before contract renewal → alert the account manager
When deal value > $50k → loop in the sales director
Always accountable: every automation run is logged with execution history (including scheduled runs), so you can see exactly when it fired, who it reached, and whether it succeeded.
