Settings

WhatsApp

Connect a WhatsApp Business account, send approved templates, and answer chats with flows and bot rules.

Overview

WhatsApp is a Settings section. An administrator connects one or more Meta WhatsApp Business accounts, then builds the messages those accounts can send. Message automations can use WhatsApp as a channel.

Go to Settings → WhatsApp. The section has four pages: Accounts, Templates, Flows and Bot Rules.

Accounts

The list shows Display Name, Whatsapp Number, Primary Account, Enable Bot, Is Active and Actions. Actions include test connection, edit and delete.

Each account stores the connection to Meta:

  • Display Name and WhatsApp Number.
  • Phone Number ID and Business Account ID.
  • Access Token, Webhook Verify Token and App Secret.
  • Graph API Version, which defaults to v21.0.
  • Primary Account, Enable Bot and an optional Default Bot Rule.

Use Test Connection on an account to check that Horilla can reach Meta with the saved token. An incoming webhook is accepted only when Meta's signature matches that account's app secret. A missing or mismatched signature is rejected.

Templates

The list shows Template Title, Template Name, Language Code, Category, Related Model and Actions.

A template is a message Meta has approved for the account. The form records the template title, the Meta template name, language code, category, sample body, components, the related CRM model, and the record fields used as variables. Sending uses the account the template belongs to.

Flows

The list shows Flow Title, Flow Name, Button Text, Account, Is Active and Actions.

A flow is a Meta WhatsApp Flow attached to an account and a related model. The record stores the flow title, the Meta flow, the flow name and the button text shown to the contact.

Bot Rules

The list shows Flow Name, Account, Trigger Type, Trigger Keywords, Is Active, Version and Actions.

A bot rule answers a conversation without an agent. It belongs to one account and can be limited to a related model. The rule has a trigger type, trigger keywords, a version, and a retrigger cooldown with a unit (so the same person is not walked through the rule again immediately).

The rule is a graph of nodes and edges. One node is the start. A session remembers the conversation, the current node and any variables. A delayed step can resume later.

Chats

  • A conversation linked to a CRM record follows that record's access. Someone who cannot see the record cannot open the chat.
  • A conversation with no live record needs the WhatsApp conversation permission.
  • The API uses the same model permissions and stays inside the caller's company.
  • An empty inbox uses the shared empty state.

Expected Behaviour

  • Accounts, templates, flows and bot rules are listed, created, edited and deleted from Settings.
  • A webhook without a valid signature does not create or update a message.
  • Turning the bot on for an account does not reply until a bot rule is available to run.
